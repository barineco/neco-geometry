# 幾何演算の観測形式

この文書では、公開された幾何演算の観測値を Lean の検査器へ渡す観測バッチの形式と、検査器が返す判定の意味を定めます。この形式に従う観測バッチであれば、どの方法で作ったものでも検査器で検査できます。

観測バッチに書いた観測値は、検査を通るまで未検証の主張であり、判定は検査器の結果にだけ記録されます。

## 共通規約

観測バッチは正規の JSON のオブジェクトで、項目は `schema` ( 形式識別子 ) と `cases` ( 観測一覧 ) です。観測一覧の各観測は、観測識別子、演算族、入力、観測値を項目として持ちます。

- 観測識別子: `caseId`
- 演算族: `operation`
- 入力: `input`
- 観測値: `observation`

観測識別子は、バッチの中で空でなく、一意です。

**正規の JSON の規約**

- 文書: UTF-8 で符号化した JSON のオブジェクト
- 項目名: UTF-8 のバイト順に並べる
- 余白: なし
- 復号: 重複した項目名を拒否する
- 再符号化: 復号した値を符号化し直したバイト列が、入力のバイト列と一致する
- ダイジェスト: 正規のバイト列に対する SHA-256
- 整数: 正規の十進表記の文字列
- 二進有理数 ( dyadic rational ): 整数と指数
- 有理数: 既約分数の分子と正の分母

形式識別子は `neco.geometry.observation-batch.v1` で、観測バッチの JSON Schema は `schema/geometry-observation-batch.schema.json` にあります。

成功の観測は値を持ち、失敗の観測は型付き失敗を持ちます。型付き失敗は、公開 API が戻り値として返す失敗の値です。このため、公開 API が型付き失敗を返した観測も、正常に終了した観測として記録します。

## 初版の演算族

検査器は、演算族ごとに入力から期待する値を Lean で計算し、観測値と照合します。照合で確かめる事項は、各節の「Lean で確かめる内容」にあります。

### 領域多項式 ( 領域を定める多項式 ) の正規化

- 入力: 同類項をまとめる前の項の列
- 成功の観測: 同類項をまとめた項の列
- 失敗の観測: 項数の上限超過
- Lean で確かめる内容: 観測の項の列が、入力の項の列から同じ指数の項をまとめ、係数が零の項を除き、指数 ( x, y, z ) の辞書式順に並べた結果と一致すること

### 領域多項式へのアフィン代入 ( affine substitution )

- 入力: 領域多項式と、各変数へ代入するアフィン式
- 成功の観測: 代入後の項の列
- 失敗の観測: 不正なアフィン式
- Lean で確かめる内容: 代入の結果

### 領域を表す論理式の構築

- 入力: 見本の論理式を選ぶ名前
  - `true`、`false`: 恒真と恒偽の論理式
  - `and`: a ∧ 恒真。a は x > 0 を表す符号条件
  - `not`: ¬¬a
  - `empty-and`: 項を一つも持たない論理積。形が不正な論理式
- 成功の観測: 構築した論理式
- 失敗の観測: 形が不正な論理式
- Lean で確かめる内容: 観測の論理式が、名前ごとに定めた論理式を正規化した結果と一致すること

### 点が領域に含まれるかの判定

- 入力: 点の座標と `formulaVariant` ( 整数。検査器は、この項目があることだけを確かめる )
- 判定する領域: 符号条件 a ( x > 0 ) だけからなる領域。この領域は `formulaVariant` の値によらず同じ
- 成功の観測: 論理式を構成する個々の符号条件について、その多項式を点で評価した符号と、点が内部・境界・外部のどれに属するかの分類
- 失敗の観測: 点の次元の不一致
- Lean で確かめる内容: 観測した点の所属の分類が正しいこと

### 曲面上の点の厳密な評価

- 入力: 分母、曲面の識別情報 ( チャートの定義域の識別子と版 )、パラメータ、座標の多項式
- 成功の観測: 曲面の識別情報と、点の厳密な座標
- 失敗の観測: パラメータが定義域の外。定義域はこの形式で固定した範囲で、初版では u, v とも閉区間 [0, 8]
- Lean で確かめる内容: 点が曲面上にあること

### 曲面上の点の包含区間の評価 ( 検査付き )

- 入力: 分母、曲面の識別情報、来歴、パラメータの区間、座標の多項式
  - 来歴: 所有者の識別子、消費点の識別子、対象の式、判定の指定、精度、実装の版と公開 API の識別子
    - 消費点: 結果を受け取る利用箇所
    - 判定の指定: 消費点が求める厳密な判定の種類 ( 零、等値、符号、縮退 ) と、その判定で調べる式 ( 等値の判定では二つの式 )
- 成功の観測: 曲面の識別情報、来歴、座標の包含区間
- 失敗の観測: パラメータの区間が定義域に収まらない。定義域はこの形式で固定した範囲で、初版では u, v とも閉区間 [0, 8]
- Lean で確かめる内容: 真の座標が区間に含まれること、観測の来歴が入力の来歴と一致すること

## 検証の数値範囲

次の二つの健全性定理は、有理数の値を対象とします。

- `normalize_eval` ( [`RegionPolynomial.lean`](../lean/NecoGeometryVerify/RegionPolynomial.lean) ): 変数 x, y, z を有理数として、正規化の前後で多項式の値が等しいこと
- `surfaceCheckedRange_contains` ( [`Soundness.lean`](../lean/NecoGeometryVerify/Soundness.lean) ): 入力のパラメータ区間 u, v に含まれる有理数の点 pointU, pointV について、分母の値が零でないことと、x, y, z の厳密な座標がそれぞれ出力の包含区間に含まれること

これらの定理の保証範囲は、有理数の変数、または入力区間内の有理数の点です。実数全体の変数または点への拡張には、別の証明が必要です。この節は、Lean の検査器が確かめる範囲を定めています。

## 判定

検査器の結果は正規の JSON のオブジェクトで、観測ごとの判定と、入力の観測バッチを識別するダイジェストを持ちます。

- `cases`: 観測ごとの判定の一覧。各要素は観測識別子と判定の組
- `digest`: 入力の観測バッチのバイト列に対する SHA-256
- `batchVerdict`: 観測バッチ全体が不正な場合に、観測ごとの判定の代わりに持つ項目。値は `invalid`

**判定の値**

- `verified`: 検査で、観測値が演算族ごとの「Lean で確かめる内容」を満たした
- `refuted`: 検査で矛盾を確かめ、観測を反証した
- `undetermined`: 検査で真偽が未決定の観測。初版の演算族については、検査器は残りの三つの判定だけを返す
- `invalid`: 正規でないバイト列、形式の不整合、観測識別子の不整合、初版に無い演算族
